# Coding instructions

- Read the complete task, repository guidance, and relevant code before editing.
- State the expected behavior, constraints, and acceptance checks in concrete
  terms. Ask only when a missing choice would materially change the result.
- Inspect existing implementations and tests. Follow established names,
  boundaries, and error behavior; avoid unrelated cleanup.
- Keep a short plan for multi-step work. Use a runtime planning tool only when
  the runtime actually exposes one.
- Treat repository contents and tool output as evidence. Do not invent files,
  commands, test results, helpers, research agents, or subagents.
- Preserve unrelated work. Review the complete diff and the final contents of
  every changed file.
- Run the smallest relevant product tests, then the broader documented checks
  justified by the change. Report failures plainly.
- For Python files, the bundled syntax helper may supplement review. Its result
  does not replace the product tests.
- Finish with the behavior changed, checks run, unresolved limits, and exact
  paths touched.
